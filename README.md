# 二手机批签（PTI）· 测试版 App

**这不是正式版，是给 Ji 先装上看看的测试版。** 用老高参考图里的模拟数据和图片做的，正式客户流程、样例数据还没到，正式版要按 `pti-batch-sign/ARCHITECTURE.md` 重做服务端 + Room 持久化。

## 测试版里有什么

- 登录：手机号 + 密码，界面显示员工姓名（见下方测试账号）。
- 底部导航 4 个 Tab（参考 WrtHub 结构）：查机 / 申请记录 / 报警 / 我的，切换不重建页面。
- 查机：按机号 / 名称 / 序列号搜索，客户筛选，在保 / 临近到期 / 已过保 / 长期未批签筛选。
- 机器详情：机号、电源箱 / 板子序列号、起止与到期日、照片（可拍照新增）、申请记录。
- 申请批签：服务端规则的测试版实现——已过保直接拦截不生成单号，在保 / 临近到期通过并生成 `PTI-YYYYMMDD-序号`。
- 发货核验：无单不发货，单号不存在、与机号不匹配、状态不是已通过，一律拒绝发货。
- 扫码：条码与二维码都能扫（CameraX + ML Kit），扫机号 / 序列号进详情，扫单号进核验。
- 拍照：机器详情里拍照，照片存手机本地（测试版重启后模拟数据会恢复，实拍照片不随模拟数据保存）。
- 管理（仅管理员）：账号、客户、机器、单据（作废）、规则展示、审计日志查看。

## 安装

GitHub Actions 构建成功后，在对应 Run 的 Artifacts 里下载 `pti-batch-sign-test`，里面是 `app-debug.apk`，手机上直接安装即可（测试版未签名，用 debug 包）。

## 测试版与正式版的区别（别把测试版当正式用）

- 数据只在内存里，重启恢复模拟数据；正式版走 Room + 服务端 + 审计不可删。
- 规则只做了“已过保拦截”这一条；保修期时长、起算口径、审批流、通知、Excel 导入导出，正式版待客户确认后才做。
- 管理里的规则、导入导出目前是展示 / 占位，不是正式功能。
- 没有 tag、没有 Release，安装只走 Actions artifact。

## 技术栈

Kotlin + Jetpack Compose（Material 3），与矽科 App 同一套；图标测试版用 Material Icons 占位，正式版按 ICONS.md 换 Lucide 线条风 VectorDrawable。
